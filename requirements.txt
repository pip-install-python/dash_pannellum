# AI/LLM Integration & SEO — from PyPI; the vendored 2.0.0 tarball is gone.
# 2.5.1 was the Tier-B SEO standard: configure_seo (icons, social card,
# publisher/sameAs), crawler <title> carrying the site name, per-page
# title/image_url/schema_type reaching the crawler document, /favicon.ico
# answered with a redirect instead of the app shell, and a prerender that
# no longer clobbers the browser's per-page <title>. Below 2.3.4
# `resolve_site_title` does not exist and this site's published identity
# (the /llms.txt H1, the llms viewer's brand chip) silently degrades to
# `app.title`. tests/test_site_identity.py asserts the installed version,
# and CI asserts it again inside the image.
#
# 2.6.0 raises it to the honesty standard: sitemap <lastmod> is emitted
# verbatim from register_page_metadata(lastmod=) and OMITTED when unset.
# The floor is load-bearing for HONESTY, not crash avoidance — pre-2.6
# packages swallow `lastmod=` into **kwargs and ignore it silently, so
# below the floor every date this repo stamps is dropped and the sitemap
# goes back to swearing everything changed at build time. 2.6.0 also adds
# icon autodiscovery, which is why the favicon pixels had to be this site's
# own BEFORE this floor moved: discovery would otherwise have cemented the
# template's mark as this host's identity. They were already correct here
# (all eight files distinct from the template), so the ordering rule cost
# nothing on this host — tests/test_seo_icons.py pins discovery and the
# explicit configure_seo(icons=) list to the same set.
# 2.6.1 floor, and the floor is what makes it STICK: the universal
# prerender ships VISIBLE to non-JS consumers, where 2.6.0 wrapped it in
# a literal `hidden` attribute and every visibility-respecting reader saw
# only "Loading...". Measured on this host 2026-08-22: a deploy that
# changed only lib/ left the image on 2.6.0, because Dockerfile:25-26
# COPY+install requirements.txt long before COPY lib, so both dependency
# layers were cache hits and pip never re-resolved. Moving this line is
# what invalidates them. run.py's LLMS_PKG_FLOOR and two asserts in
# ci.yml encode the same number — grep the number, not the file.
dash-improve-my-llms[flask,fastapi]>=2.6.1
